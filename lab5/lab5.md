# ЛР №5 — ICMP и IP: параллельный ping, traceroute, Smurf

Изучение протокола ICMP и особенностей его программирования (raw-сокеты),
а также заголовка протокола IP.

## Состав

- `net.py` — сборка/разбор ICMP-пакетов, контрольная сумма, разбор IP-заголовка.
- `ping.py` — параллельный ping нескольких хостов и режим traceroute.
- `smurf.py` — учебная демонстрация Smurf-атаки (spoofing источника + broadcast).

## Что реализовано

- **Параллельный ping**: один поток на каждый хост.
- **Общий сокет + `MSG_PEEK`**: все потоки читают из одного raw-сокета; пакет
  удаляется из буфера только после проверки, что ICMP `id` ответа совпадает с
  `id` данного потока. Чужие пакеты остаются для других потоков.
- **Метка времени в теле пакета**: отправляется при echo-request, RTT считается
  по ней при приёме.
- **Разные обработчики**: echo-reply, «время жизни истекло» (TTL exceeded),
  «хост недостижим» (destination unreachable).
- **traceroute**: путь до узла определяется наращиванием TTL.
- **Smurf**: в IP-заголовке источник = адрес жертвы, пакет шлётся на broadcast.

## Требования

Raw-сокеты требуют прав администратора:

- Linux/macOS: запуск через `sudo`.
- Windows: запуск от имени администратора.

Только стандартная библиотека Python 3.

## Запуск

Параллельный ping нескольких хостов:

```bash
sudo python3 lab5/ping.py 8.8.8.8 1.1.1.1 ya.ru --count 4
```

Traceroute до узла:

```bash
sudo python3 lab5/ping.py --trace 8.8.8.8 --max-hops 30
```

Демонстрация Smurf-атаки (**только в своей учебной сети!**):

```bash
sudo python3 lab5/smurf.py --victim 192.168.1.50 --broadcast 192.168.1.255 --count 20
```

Наблюдать поток echo-reply на узле-жертве через **Wireshark**
(фильтр `icmp`).

## Контрольные вопросы

1. Работа программы traceroute — на TTL и ICMP «time exceeded».
2. Механизм Smurf-атаки, угрозы, защита (запрет directed broadcast, ingress-фильтрация).
3. Назначение полей заголовка IP.
